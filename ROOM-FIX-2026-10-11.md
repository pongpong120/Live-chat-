# Room + Rocket Crash fix — 2026-10-11

## Fixed
1. **Room chat messages not visible** — an old rule (`#chat-log {height:100%}`) pushed the bottom-anchored message list below the screen, behind the toolbar. The log now takes only the free space under the rules/announcement cards. Also: the Send button used to exist only while the input had focus, so tapping it could hide it before the click registered; it now shows whenever there is text and keeps keyboard focus.
2. **Seats** — all 12 seats are one small fixed size (`--pp-seat-size`, 42–50px), perfectly circular, photo/voice effects clipped to a circle.
3. **Inbox icon in room** — visibility was only refreshed when an unread event happened. It is now refreshed on room open, every room-state update, and by a light 1.5s sync; CSS forces it visible when not `.hidden`. It no longer sits under the mic-invite bar.
4. **Rocket Crash** — the game page opened its own Socket.IO connection which was never `identify`-ed, so the server always answered "authentication required" (balance `—`, no timer, no betting). It now talks through the app's already-authenticated socket (postMessage bridge in `app.js`), so it works while inside a room.
   - Server (`games/rocketCrash.js`) is now a real game: 8s betting window → live multiplier ticks → crash → 4s pause. Crash point and cash-out multiplier are computed on the server only.
   - Wallet: same live path as Lucky Fruit (`productionWallet` when enabled, else `user.diamonds` + `saveUsers`), with per-user serialization, `logTransaction`, `pushWalletUpdate`.
   - Bets 100 – 100,000 Diamonds (`ROCKET_MAX_BET`), house edge 4% (`ROCKET_HOUSE_EDGE`, max 20%). One bet per user per round.
   - Restart safety: open bets are mirrored to `rocket_crash_open_bets.json`; any unsettled bet is refunded at next boot.
   - Page shows live Diamond balance, round number, countdown / flight timer, history, sound toggle.

## NOT checked / limitations
- Not run against a live server with real sockets, login, Redis or PostgreSQL (dependencies are not installed here). Please test on your Termux server: open a room, tap More → Rocket Crash, place a bet.
- Round state is per Node process; with several instances each would run its own round.
- A mid-round crash of the server refunds bets on restart; a failed production-wallet payout is logged (`Rocket Crash payout FAILED`) and shown to the player, but not auto-retried.
- Real-Diamond betting is a business/legal decision for your markets; edge and limits are configurable via env.
